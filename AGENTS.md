# Инструкции для Codex: PatternExporterNX

PatternExporterNX — независимый форк `isinicyn/FlatPatternExporter`, сопровождаемый `mrTorch222`: https://github.com/mrTorch222/PatternExporterNX. Автор исходного проекта — Sinicyn Ivan Victorovich; лицензия MIT сохранена в `LICENSE.txt`, сведения о происхождении — в `NOTICE.md`. Каталоги проектов и пространства имен `FlatPatternExporter` сохранены для совместимости.

## Язык и рабочая среда

- Общайся с пользователем на русском языке.
- Разработка и окончательная проверка выполняются на Windows 10/11 x64 в Visual Studio Code.
- Целевая CAD-система: Autodesk Inventor 2027.
- Основной проект: C# 12, WPF, .NET 8.0, `win-x64`.
- Это отдельное WPF-приложение, подключающееся к уже запущенному Inventor через COM API. Не превращай его в Inventor Add-In и не добавляй `.addin`-манифест без отдельного запроса.
- Соблюдай `.editorconfig`: C# и XAML — UTF-8 с BOM и CRLF; Markdown — UTF-8 без BOM. В проекте есть кириллица.
- Перед изменениями полностью прочитай `CLAUDE.md`, `README.md`, `.editorconfig`, `LICENSE.txt` и релевантные исходники.

## Цель текущей доработки

Нужно сохранить существующее поведение экспортера и добавить четыре изолированные возможности:

1. Очистить интеграцию с Inventor API и сделать сборку явно ориентированной на Inventor 2027.
2. Добавить преобразование DXF-сплайнов, заданных control points, в сплайны, заданные fit points.
3. Добавить выбираемые колонки `Длина реза, мм` и `Длина реза, м`.
4. Добавить выбираемую диагностическую колонку `Единицы документа`, которая показывает текущие единицы длины файла детали Inventor. Геометрию и единицы DXF автоматически не менять.

Не делай крупный рефакторинг UI, сканера документов, именования файлов, обновлятора или механизма пресетов, если он не требуется для этих функций.

## Сначала зафиксируй базовое состояние

Перед реализацией:

1. Выполни `git status --short` и не перезаписывай пользовательские изменения.
2. Собери Release-конфигурацию до правок.
3. Запусти текущую программу с Inventor 2027 и экспортируй минимум одну простую развертку.
4. Сохрани эталонные DXF:
   - простой контур с отверстием;
   - деталь со сплайном control-point;
   - файл, который сейчас определяется как метры и открывается программой резки с ошибочным масштабом.
5. Запиши фактические `$INSUNITS`, `$MEASUREMENT`, диапазон координат и представление `SPLINE` в эталонах.

Если базовая версия не собирается или не экспортирует, сначала сообщи точную ошибку. Не маскируй исходную проблему последующими изменениями.

## Обновление Inventor API до 2027

- Сохрани `TargetFramework` `net8.0-windows...`, C# 12 и `win-x64`: Inventor 2027 бинарно совместим с существующими .NET 8 интеграциями.
- Обнови ссылку `Autodesk.Inventor.Interop.dll` с Inventor 2026 на Inventor 2027.
- Не копируй и не публикуй Autodesk Interop DLL вместе с приложением, если это не разрешено Autodesk; предпочтительно выставить `Private=false`.
- Убери жестко прошитый путь из единственного места сборки: введи MSBuild-свойство вроде `InventorInstallDir`, значение по умолчанию для Inventor 2027 и понятную ошибку сборки, если interop не найден.
- Обнови упоминания 2026 в `README.md` и `CLAUDE.md`.
- Не подключай новые API Inventor 2027 без необходимости. Для экспорта по-прежнему используй `FlatPattern.DataIO.WriteDataToFile`.

## Архитектура DXF post-processing

- Оставь `DxfExporter` координатором экспорта.
- Вынеси новую обработку в отдельный сервис, например `Utilities/DxfPostProcessor.cs`; не раздувай `DxfOptimizer`.
- Порядок обработки одного файла:
  1. Inventor DataIO создает DXF.
  2. Post-processor загружает DXF один раз.
  3. При необходимости преобразует control-point splines в fit-point splines.
  4. Вычисляет длину реза по итоговой геометрии без изменения масштаба.
  5. Применяет требуемую версию DXF/оптимизацию.
  6. Сохраняет через временный файл и атомарно заменяет целевой файл.
  7. Только после успешного сохранения обновляет строку таблицы и строит preview.
- Не загружай и не пересохраняй один DXF несколькими независимыми проходами.
- Ошибка post-processing означает ошибку экспорта этой детали. Нельзя оставлять частично переписанный DXF и помечать строку как успешную.
- Сохраняй слои, цвета, типы линий, lineweight, normal/elevation и поддерживаемые XData сущностей.

## Преобразование control points в fit points

- Добавь третий вариант в существующий режим обработки сплайнов: `FitPoints`. Не меняй числовые значения существующих enum `Lines = 0` и `Arcs = 1`; новый вариант добавляй в конец для совместимости настроек.
- Этот режим отличается от Inventor DataIO `SimplifySplines=True`: результат должен оставаться сущностью `SPLINE`, а не превращаться в линии или дуги.
- Для каждого control-point spline:
  - вычисли точки на исходной NURBS-кривой;
  - подбирай fit points адаптивно до заданного допуска, а не фиксированным малым числом сегментов;
  - корректно обрабатывай open/closed/periodic splines;
  - создай новую fit-point spline средствами netDxf;
  - перенеси графические свойства и слой;
  - проверь максимальное отклонение от исходной кривой.
- Не считай простое копирование control points в список fit points корректным преобразованием: у этих точек разный геометрический смысл.
- Для неподдерживаемого или вырожденного сплайна не делай молчаливую порчу. Верни диагностическую ошибку с именем файла, слоем и причиной.
- Приемка режима:
  - в итоговом DXF есть `SPLINE` и ненулевое число fit points;
  - контур визуально и численно совпадает с исходным в пределах допуска;
  - тестовый файл импортируется целевой программой резки без ручного выбора Fit;
  - длина замкнутого контура не меняется больше допустимой погрешности.

## Диагностическая колонка единиц

- Добавь системное поле `DocumentUnits` и выбираемую колонку `Единицы документа` / `Document units`.
- Заполняй поле во время сканирования детали из `PartDocument.UnitsOfMeasure.LengthUnits` (или эквивалентного API Inventor 2027), чтобы значение было видно до экспорта.
- Показывай короткие однозначные обозначения: как минимум `мм`, `м`, `см`, `дюйм`, `фут`; неизвестное значение показывай как `Неизвестно`, не как миллиметры.
- Это только диагностика. Не изменяй UnitsOfMeasure документа, параметры детали, числовые координаты DXF, `$INSUNITS`, `$MEASUREMENT`, масштаб блоков или любые другие данные.
- Не добавляй режим `ForceMillimeters`, автоматическое масштабирование или автоматическую перезапись единиц.
- Пользователь сам открывает отмеченную деталь в Inventor и меняет единицы перед повторным сканированием/экспортом.
- Если полезно для диагностики, после экспорта можно проверить заголовок DXF и записать предупреждение при расхождении с единицами документа, но нельзя автоматически исправлять файл. Не добавляй отдельную колонку DXF без согласования.

## Колонки длины реза

- Добавь в `PartData` числовое каноническое значение, например `double? CutLengthMm`, и производное `CutLengthM = CutLengthMm / 1000.0`.
- В `PropertyMetadataRegistry` зарегистрируй выбираемые системные колонки:
  - `CutLengthMm` — `Длина реза, мм`;
  - `CutLengthM` — `Длина реза, м`;
  - `DocumentUnits` — `Единицы документа`.
- Добавь русские и английские ресурсы. Колонки должны участвовать в сохранении порядка, поиске/сортировке и экспорте Excel/CSV так же, как другие системные колонки.
- Храни число как число, а не как локализованную строку. Форматирование и округление делай на уровне UI/Excel.
- На первом этапе эти поля являются выбираемыми колонками, но не токенами имени файла: длина становится известна только после формирования DXF. Не создавай циклический экспорт ради имени файла без отдельного решения пользователя.
- Значение заполняется после успешного post-processing и сбрасывается при новом сканировании или неуспешном экспорте.
- Базовое определение длины реза: сумма длин итоговых сущностей на включенных слоях наружного и внутренних профилей (`OuterProfileLayer`, `InteriorProfilesLayer`) после преобразования сплайнов. Линии сгиба, касательные, construction geometry и центры дуг не учитывать.
- Канонический `CutLengthMm` допустим только после явного перевода результата измерения через единицы, прочитанные из DXF/документа. Этот перевод нужен лишь для отображения длины в мм и м; он не должен менять сам DXF.
- Если включенные feature/unconsumed-sketch слои реально используются как траектория лазера, не включай их автоматически: добавь отдельную явную настройку слоев, участвующих в расчете, либо согласуй это с пользователем.
- Поддержи как минимум `LINE`, `ARC`, `CIRCLE`, `ELLIPSE`, `LWPOLYLINE/POLYLINE` и `SPLINE`. Для кривых используй аналитическую длину, где она доступна, иначе адаптивную аппроксимацию с контролируемой погрешностью.

## Совместимость настроек и UI

- Новые поля в JSON-настройках должны иметь значения по умолчанию, чтобы старый `%AppData%\FlatPatternExporter\settings.json` продолжал загружаться.
- Не переименовывай существующие JSON-поля и не меняй номера существующих enum.
- Все новые строки добавляй и в `Resources/Strings.resx`, и в `Resources/Strings.ru.resx`.
- Используй существующий `PropertyMetadataRegistry`, динамическое создание колонок, механизм `ColumnOrder` и текущие стили WPF.
- Не добавляй второй независимый механизм колонок или настроек.

## Проверки

- Для чистой DXF-логики создай тестовый проект без зависимости от запущенного Inventor. Храни минимальные текстовые DXF fixtures в репозитории.
- Обязательные тесты:
  - control-point spline становится fit-point spline;
  - отклонение кривой не превышает tolerance;
  - свойства слоя сохраняются;
  - `DocumentUnits` корректно читается для деталей в мм и м;
  - экспорт не изменяет единицы документа, DXF header и координаты;
  - длина реза корректно переводится в мм и м для известных единиц;
  - неизвестные/unitless единицы не трактуются молча как миллиметры;
  - длины line/arc/circle/polyline/spline суммируются верно;
  - не-режущие слои исключаются;
  - старый JSON settings загружается с новыми defaults.
- После автоматических тестов выполни ручную проверку на Windows с Inventor 2027 и целевой программой резки.
- Сравни до/после: число сущностей, набор слоев, bounding box, суммарную длину реза и визуальный preview.

## Команды и отчет о результате

Основные команды на Windows:

```powershell
dotnet restore .\PatternExporterNX.sln
dotnet build .\PatternExporterNX.sln -c Release -p:Platform=x64
dotnet test .\PatternExporterNX.sln -c Release
```

В конце работы сообщи:

- какие файлы изменены;
- какие тесты и ручные проверки пройдены;
- на каких DXF и версиях Inventor проверено;
- максимальную измеренную ошибку spline conversion;
- правило расчета длины реза;
- что осталось непроверенным.

Не заявляй, что интеграция с Inventor или программой резки работает, если была выполнена только компиляция.
