# Лист приёмки деталей

## Цель

Добавить печатный лист приёмки, в котором каждая уникальная деталь представлена отдельной карточкой: изображение, обозначение, наименование, требуемое количество и пустое поле для фактического наличия. Перед экспортом пользователь должен отдельно настроить ракурс каждой детали, включая перспективный вид.

Первый рабочий формат — XLSX. Он уже поддерживается проектом через ClosedXML, сохраняет прозрачные PNG и подходит для печати и ручного заполнения. PDF следует добавить вторым форматом после утверждения макета.

## Что уже есть в проекте

- `ThumbnailGenerator` получает сохранённый preview из файла, Inventor, Apprentice или Windows Shell. Это быстрый fallback, но его ракурс заранее зафиксирован и фон не гарантированно прозрачный.
- `DxfThumbnailGenerator` строит плоское изображение развёртки. Оно подходит для листовых деталей, но плохо идентифицирует согнутую деталь.
- `ExcelExportService` уже вставляет PNG в XLSX, однако формирует обычную таблицу, а не сетку карточек.
- `PartData` содержит preview, обозначение, описание, материал, количество, массу и параметры листового металла.
- `FrameMemberData` содержит обозначение, описание, материал, длину и количество. Изображения в этой модели пока нет.
- Иерархический расчёт количества и объединение копий уже выполняются до экспорта; лист приёмки должен использовать итоговое количество из строки, а не пересчитывать структуру самостоятельно.

## Возможности Inventor 2027

### Прозрачный рендер

`Camera.SaveAsBitmapWithOptions` сохраняет PNG или TIFF и принимает `TransparentBackground=True`. Метод появился в Inventor 2026.1, поэтому он доступен для целевой версии Inventor 2027. Это основной путь для изображения без фона.

Источник: [Camera.SaveAsBitmapWithOptions](https://help.autodesk.com/cloudhelp/2027/ENU/Inventor-API/files/Camera_SaveAsBitmapWithOptions.htm).

### Индивидуальный ракурс и перспектива

Камера Inventor предоставляет `Eye`, `Target`, `UpVector`, `ViewOrientationType`, `Perspective` и `PerspectiveAngle`. Значит, для каждой детали можно хранить собственную ориентацию и отдельно включать перспективу.

Источники: [Camera object](https://help.autodesk.com/cloudhelp/2027/ENU/Inventor-API/files/Camera.htm), [Camera perspective](https://help.autodesk.com/cloudhelp/2024/ENU/Inventor-API/files/Camera_Perspective.htm), [пример вращения камеры](https://help.autodesk.com/cloudhelp/2027/ENU/Inventor-API/files/DriveCamera_Sample.htm).

Для рендера без переключения активного окна можно создать transient camera, назначить `PartComponentDefinition` в `SceneObject`, применить ракурс, вызвать `Fit` и сохранить изображение. Этот вариант нужно проверить живым тестом в Inventor 2027: во время исследования запущенный экземпляр Inventor через COM был недоступен.

### Настоящий технический эскиз

Inventor позволяет создавать base drawing view с произвольной камерой и стилем `HiddenLineRemoved`. Это даёт чистый контур, близкий к изображению в образце. Метод поддерживает стандартные и произвольные ракурсы, включая камеру пользователя.

Источник: [DrawingViews.AddBaseView](https://help.autodesk.com/cloudhelp/2022/ENU/Inventor-API/files/DrawingViews_AddBaseView.htm).

Такой вид требует временного drawing document и заметно тяжелее прозрачного PNG. Автоматические размеры также придётся размещать отдельно. Поэтому рекомендуемый порядок:

1. прозрачный shaded PNG с выбранным ракурсом;
2. hidden-line изображение без размеров;
3. технический эскиз с габаритными размерами и диаметрами там, где геометрия позволяет определить их однозначно.

## Предлагаемый интерфейс

Добавить отдельную вкладку `Лист приёмки`, доступную после сканирования.

Левая часть вкладки содержит список деталей с обозначением, наименованием, количеством и индикатором готовности изображения. Центральная часть показывает крупный preview выбранной детали. Правая часть содержит настройки карточки и листа.

Управление preview:

- вращение мышью вокруг центра модели;
- колесо мыши — масштаб;
- средняя кнопка или `Shift` — панорамирование;
- `Вписать`, `Сбросить`, `Спереди`, `Сверху`, `Справа`;
- четыре изометрических вида;
- переключатель `Перспектива` и угол перспективы;
- `Применить этот ракурс ко всем похожим деталям`;
- `Следующая деталь` для последовательной подготовки всего листа.

WPF не должен встраивать полноценное окно Inventor. Движение мыши меняет параметры камеры, после чего сервис перерисовывает PNG с задержкой 100–200 мс. Во время движения допустим preview меньшего разрешения; экспорт создаёт окончательное изображение 800–1200 px.

## Модель данных

Общий модуль должен работать и с листовым металлом, и с Frame Generator.

```text
AcceptanceSheetItem
  SourceKey             FullFileName + ModelState
  PartNumber
  Description
  Material
  QuantityRequired
  QuantityAccepted      пустое поле в печатной форме
  AdditionalFields
  CameraState
  RenderMode
  PreviewPng

AcceptanceCameraState
  DirectionX/Y/Z        нормализованное направление взгляда
  UpX/Y/Z               нормализованный верх камеры
  Perspective
  PerspectiveAngle
  FitMargin

AcceptanceSheetSettings
  PaperSize             A4/A3
  Orientation           книжная/альбомная
  CardsPerRow           1/2/3
  RenderMode            shaded/hidden-line/saved-thumbnail
  TransparentBackground
  ImageResolution
  VisibleFields
  CardTemplate
```

Абсолютные координаты `Eye` и `Target` сохранять не следует: они зависят от размера и положения геометрии. Надёжнее хранить нормализованное направление, `UpVector`, режим перспективы и отступ `Fit`.

В первой версии ракурсы живут в текущей сессии. После проверки UX их можно сохранять в отдельный sidecar-файл проекта. Записывать десятки камер и PNG в общий `%AppData%\FlatPatternExporter\settings.json` не следует.

## Сервисы и границы модулей

```text
AcceptanceSheetItemFactory
  SheetMetal adapter -> PartData
  Frame adapter      -> FrameMemberData

AcceptancePreviewService
  InventorCameraRenderer
  SavedThumbnailFallback
  DxfPreviewFallback

AcceptanceSheetComposer
  строит независимую модель страниц и карточек

AcceptanceExcelExporter
  превращает модель страниц в XLSX

AcceptancePdfExporter
  второй этап, использует ту же модель страниц
```

COM-вызовы Inventor должны выполняться последовательно через STA. Рендеры нужно кэшировать по ключу `SourceKey + CameraState + RenderMode + Resolution`, а временно открытые документы закрывать только в том случае, если сервис открыл их сам.

## Макет XLSX

Начальный макет A4:

- две карточки в строке;
- изображение слева, данные справа;
- обозначение и наименование сверху;
- крупное требуемое количество;
- пустое поле `Наличие`;
- опциональные поля `Материал`, `Толщина/длина`, `Масса`, `Комплект`;
- чёрные границы, белый фон, повторяемый размер карточки;
- print area, поля страницы и разрывы страниц задаются явно;
- прозрачный PNG помещается поверх белой области карточки.

Поля карточки должны использовать существующий реестр свойств и тот же блочный конструктор, что применяется для имени файла и текста гибов. Тогда пользователь сможет менять состав и порядок подписей без новой разметки для каждого свойства.

## Этапы реализации

### Этап 1. Вертикальный прототип

- transient camera для одной открытой детали;
- стандартный изометрический и перспективный ракурсы;
- PNG с альфа-каналом;
- проверка на детали, сборке Frame Generator и модельном состоянии;
- восстановление состояния Inventor после рендера.

Критерий: одинаковый результат при открытом и закрытом исходном документе, модель не меняется и не получает признак несохранённых изменений.

### Этап 2. Редактор ракурсов

- общая модель камеры;
- мышь, стандартные виды, fit и perspective;
- последовательный просмотр всех деталей;
- кэш и отмена фонового рендера;
- fallback на текущий thumbnail.

Критерий: пользователь может настроить каждую строку без перехода в Inventor и не ждёт полного рендера на каждый пиксель движения мыши.

### Этап 3. Лист и XLSX

- сетка карточек;
- настройки бумаги и полей;
- конструктор содержимого карточки;
- итоговые количества из текущей структуры;
- preview всего листа и экспорт XLSX.

Критерий: печать A4 не меняет размеры карточек и не переносит половину карточки на следующую страницу.

### Этап 4. Технический вид и PDF

- hidden-line drawing view;
- автоматические габаритные размеры для простых деталей;
- PDF на основе общей модели страниц;
- сохранение ракурсов в sidecar-файле проекта.

## Проверки

- прозрачность PNG проверяется по наличию пикселей с alpha меньше 255;
- камера после рендера сравнивается с исходной и документ остаётся неизменённым;
- перспектива и ортография дают разные, но стабильные изображения;
- одинаковые файлы с разными Model State получают разные ключи;
- одинаковая деталь из нескольких подсборок имеет одну карточку и итоговое количество после множителей;
- длинные обозначения и наименования не выходят за карточку;
- карточка никогда не разрывается между страницами;
- XLSX открывается в Microsoft Excel и LibreOffice без восстановления файла;
- отсутствие Inventor или ошибка рендера переводят строку на сохранённый thumbnail, не прерывая весь экспорт.

## Решение для первой версии

Реализовать общий лист приёмки для обеих вкладок. Использовать прозрачный shaded PNG из Inventor, индивидуальную ортографическую или перспективную камеру и XLSX с двумя карточками в строке. Сохранённые thumbnails оставить fallback. Hidden-line эскизы и размеры развивать после проверки удобства редактора ракурсов и утверждения печатного макета.
