# План доработки PatternExporterNX для Inventor 2027

PatternExporterNX — независимый форк [isinicyn/FlatPatternExporter](https://github.com/isinicyn/FlatPatternExporter), сопровождаемый [mrTorch222](https://github.com/mrTorch222/PatternExporterNX). Исходный автор — Sinicyn Ivan Victorovich; MIT License и уведомление об авторстве сохранены. См. [NOTICE.md](NOTICE.md).

## Статус подготовки форка

Оформлены имя продукта, происхождение, лицензирование дистрибутивов и адрес обновлений форка. Этапы 0–5 реализованы; автоматическая регрессия и ручной экспорт через Inventor 2027 пройдены. Импорт в целевую программу резки остается внешней приемочной проверкой. Исходная точка и ограничения проверки зафиксированы в [FORK_BASELINE.md](FORK_BASELINE.md). Решение называется `PatternExporterNX.sln`; каталоги исходных проектов и пространства имен сохраняют имя `FlatPatternExporter`.

## Принятые трактовки требований

- Программа не меняет масштаб, координаты или заголовок DXF. Она только показывает текущие единицы файла детали Inventor, чтобы пользователь сам исправил документ до экспорта.
- Для длины реза нужны две независимо выбираемые колонки: миллиметры и метры.
- Длина реза сначала считается только по наружному и внутренним режущим профилям. Сгибы, касательные и служебные слои исключаются.
- Длина реза становится известна после создания DXF, поэтому на первом этапе она не используется в имени экспортируемого файла.

## Этап 0. Эталоны и воспроизводимость

1. Собрать текущий master без изменений.
2. Проверить подключение к Inventor 2027 и обычный экспорт.
3. Подготовить три эталона: простой лист, control-point spline и две одинаковые детали с единицами документа `мм` и `м`.
4. Зафиксировать заголовки DXF, bounding box, слои, длины контуров и результат импорта в программу резки.

Результат: понятна исходная проблема, есть файлы для регрессионных тестов.

## Этап 1. Чистое обновление Inventor 2027

1. Сделать путь к Inventor interop настраиваемым через MSBuild и по умолчанию указывать Inventor 2027.
2. Добавить понятную проверку отсутствующего `Autodesk.Inventor.Interop.dll`.
3. Не включать Autodesk DLL в дистрибутив.
4. Обновить README/CLAUDE и проверить Release x64.

Результат: проект воспроизводимо собирается против установленного Inventor 2027, сохраняя .NET 8.

## Этап 2. Единый DXF post-processing pipeline

1. Ввести `DxfPostProcessor` и модель результата обработки.
2. Загружать DXF один раз после `DataIO.WriteDataToFile`.
3. Сохранять через временный файл с безопасной заменой.
4. Перенести текущую оптимизацию версии DXF в этот единый проход.
5. Обеспечить диагностическую ошибку вместо ложного статуса Success.

Результат: дальнейшие функции не создают несколько несовместимых перезаписей DXF.

## Этап 3. Диагностическая колонка единиц документа

1. Добавить поле `DocumentUnits` в `PartData` и системную колонку `Единицы документа`.
2. Во время сканирования читать `UnitsOfMeasure.LengthUnits` каждой детали.
3. Локализовать обозначения как минимум для мм, м, см, дюймов и футов.
4. Проверить, что значение видно до экспорта и обновляется после изменения детали и повторного сканирования.
5. Регрессионным тестом подтвердить, что экспорт не меняет единицы документа, DXF header и координаты.

Результат: детали с метрами сразу заметны в таблице, а решение об исправлении принимает пользователь.

## Этап 4. Control points → fit points

1. Добавить `FitPoints` в существующий выбор обработки сплайнов.
2. Реализовать адаптивную выборку исходной NURBS по tolerance.
3. Создать fit-point spline, сохранив слой и графические атрибуты.
4. Проверить open/closed/periodic варианты и вырожденные случаи.
5. Добавить количественную проверку максимального отклонения и импорт в программу резки.

Результат: DXF продолжает содержать SPLINE, но целевая программа видит его как fit-point spline.

## Этап 5. Длина реза

1. Добавить каноническое числовое `CutLengthMm` и производное `CutLengthM`.
2. Суммировать итоговые линии и кривые режущих слоев после spline conversion, не изменяя DXF.
3. Переводить измеренную длину в мм и м только для значений колонок, используя известные единицы документа/DXF.
4. Добавить обе колонки в реестр, локализацию, сортировку и Excel/CSV.
5. Сбрасывать устаревшее значение при новом сканировании и ошибках.
6. Отдельно решить, должны ли feature/unconsumed-sketch слои считаться режущими.

Результат: после экспорта таблица показывает сопоставимую длину реза в мм и м.

## Этап 6. Регрессия и приемка

1. Автотесты DXF-преобразований и совместимости старых settings.
2. Сравнение слоев, сущностей, bounding box и длин до/после.
3. Ручной экспорт из Inventor 2027.
4. Импорт в реальную программу резки без ручной смены spline mode и масштаба.
5. Только после этого обновить версию приложения и подготовить Release archive.

## Этап 7. Экспорт элементов Генератора рам

1. Добавить вторую вкладку, не смешивая состояние экспорта труб с таблицей листового металла.
2. Рекурсивно находить документы Frame Generator по `DocumentInterests`, игнорировать подавленные вхождения, группировать одинаковые IPT и считать количество.
3. Читать iProperties и параметр `G_L`, поддержать токены `{PartNumber}`, `{StockNumber}`, `{Material}`, `{Description}`, `{Length}`, `{Qty}`, `{FileName}` и безопасные уникальные имена.
4. Экспортировать каждый уникальный элемент штатным IGES Translator Add-In Inventor с выбираемыми `GeometryType`, `SolidFaceType` и `SurfaceType`.
5. Экспортировать сгруппированный BOM в Excel и UTF-8 CSV; хранить настройки вкладки в общем совместимом JSON.
6. Проверить нейминг, BOM и совместимость старых настроек автоматическими тестами; отдельно проверить интерфейс и реальный IGES на сборке Frame Generator в Inventor 2027.

Результат: реализация и автоматические тесты завершены. Ручная приемка на реальной сборке Frame Generator и проверка полученных IGES в целевой CAD/CAM-системе остаются обязательными перед выпуском.

## Рекомендуемый порядок коммитов

1. `build: target Inventor 2027 interop`
2. `refactor: add atomic DXF post-processing pipeline`
3. `feat: add document-units diagnostic column`
4. `feat: convert control-point splines to fit-point splines`
5. `feat: add cut-length columns`
6. `test: add DXF regression fixtures and acceptance coverage`
7. `feat: export Frame Generator members and BOM`

Такой порядок позволяет проверять каждую функцию отдельно и при необходимости откатывать ее без потери остальных изменений.
